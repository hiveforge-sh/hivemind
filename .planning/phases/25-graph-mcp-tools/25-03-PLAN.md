**SearchEngine additions (src/search/engine.ts):**

Add four async methods that wrap database calls and enrich with node details:

1. **queryGraphNeighbors(entityId, options?):**
   - Call this.db.queryNeighbors()
   - For each neighbor_id, fetch full node via this.db.getNode()
   - Return { neighbors: Array<{node, relationship}>, metadata: {source, executionTime, totalResults} }

2. **queryGraphSubgraph(entityId, depth, options?):**
   - Call this.db.querySubgraph()
   - For each entity_id, fetch full node
   - Return { nodes: GraphNode[], metadata: {source, executionTime, totalResults, depth} }

3. **queryGraphPath(fromEntityId, toEntityId, options?):**
   - Call this.db.queryShortestPath()
   - If found, fetch full nodes for path
   - Return { found, path: GraphNode[], edges, metadata }

4. **listRelationshipTypes():**
   - Call templateRegistry.getRelationshipTypes() (imported from templates/registry.js)
   - Return { types: Array<{id, label, description}>, metadata }

**Server additions (src/server.ts):**

1. Import generateGraphTools and Zod schemas from './mcp/graph-tools.js'

2. In ListToolsRequestSchema handler:
   - Call generateGraphTools()
   - Spread into tools array (always include, not conditional like timeline)

3. Add graph tool call handling in CallToolRequestSchema handler:
   - Check if name starts with 'query_graph_' or is 'list_relationship_types'
   - Switch on tool name:
     - query_graph_neighbors: parse with QueryGraphNeighborsArgsSchema, call handleGraphNeighbors()
     - query_graph_subgraph: parse with QueryGraphSubgraphArgsSchema, call handleGraphSubgraph()
     - query_graph_path: parse with QueryGraphPathArgsSchema, call handleGraphPath()
     - list_relationship_types: call handleListRelationshipTypes()

4. Add private handler methods:
   - handleGraphNeighbors(): resolve entity ID, call searchEngine, format results
   - handleGraphSubgraph(): resolve entity ID, call searchEngine, format results
   - handleGraphPath(): resolve both entity IDs, call searchEngine, format results
   - handleListRelationshipTypes(): call templateRegistry, format as list

5. Add formatGraphResults() helper method:
   - Group neighbors by relationship type
   - Show each node's summary (name, type, description truncated)
   - Include relationship direction indicator for asymmetric relationships

**Entity ID resolution:**
For entityId parameters, implement resolution logic:
- Try Type:name format first (e.g., "Character:john")
- Try direct ID match
- Try name search
- Return helpful error if not found with suggestions

**Result formatting per CONTEXT.md:**
- Summary info per neighbor: name, type, description (first 200 chars)
- Context-aware empty responses: "entity has no relationships" vs "entity not found"
- Relationship direction shown (outgoing/incoming arrows)
